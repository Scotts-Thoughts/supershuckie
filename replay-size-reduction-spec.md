# Replay Size Reduction (Format v4) — Implementation Spec

**Target:** Claude Code, working in the `supershuckie` repository (branch off `resume-from-replay` / `master`).
**Component:** Super Shuckie 2 replay system (`supershuckie-replay-recorder`, `supershuckie-core`, `supershuckie-frontend`).
**Companion:** the measured audit these numbers come from — https://claude.ai/code/artifact/73390dd8-e878-4014-8d75-15e6dfb42034

---

## 1. Goal

Make gen 4 / gen 5 (melonDS) and GBA (mGBA) replays **3–6× smaller** without changing what the user can do with them:

- **A keyframe every `frames_per_keyframe` frames (120 = 2 s) stays.** Scrub granularity, `go_to_keyframe` semantics and resume-from-replay are unchanged. Seeking must get *faster*, not slower.
- Everything in Phase 1 is **lossless**: every keyframe reconstructs to the exact save state that was recorded.
- Phase 2 is a deliberate, well-bounded, *cosmetic-only* trade (§7) behind a setting.
- The existing archive (346 GiB) must be convertible offline without re-recording.

Non-goals: thinning keyframes, re-emulation-based seeking, per-game RAM-map research.

---

## 2. What the audit found (why these changes and not others)

Measured on real files from `A:\Dropbox\stp-projects\programs\supershuckie 2\UserData` (HeartGold `h-ampharos-line-1-21318`, White 2 `w-butterfree-line-1-22109`, Emerald `e-geodude-1-20359`, Platinum, Crystal):

| Fact | Consequence |
|---|---|
| Files are ~99.9% keyframe bytes. The frame stream (`NextFrame`/`ChangeInput`/`WriteMemory`) costs 0.6–0.8 B/frame after zstd. | Only keyframe encoding matters. Input dedup etc. is hygiene, not size. |
| `fast_diff` emits one `u64 = offset<<32 \| word` per changed 32-bit word → ~8.5 bytes/word after the varint writer. Changes are clustered (HeartGold: ~27K words in ~2.6K runs per keyframe). | A run-length region diff is **2.7× smaller after zstd** on NDS, 1.7× on GBA, for identical information. |
| `insert_keyframe` counts every delta as a full state in `current_blob_size_undiffed`, so the 1 GiB blob cap rolls over every 55 NDS keyframes → a full 18.8 MiB state (1.9 MiB compressed) every 110 s = 24% of a HeartGold file. That accounting exists because `decompress_compressed_blob` **expands every delta into a full state** (~1 GiB RAM per decompressed NDS blob). | Materialise deltas lazily in the player; then chains can run ~15 minutes and restarts become <5% of the file. |
| The 12.5%-changed bail-out in `fast_diff` makes 6.5–8.5% of Emerald keyframes full 516 KiB states; a region diff of the same keyframes is 2.3× smaller compressed. | Remove the bail-out. |
| `compress_data` uses one-shot `ZSTD_compress` at level 3. Level 9 costs nothing (132–177 MiB/s) and gives 8–18%. | Default to 9 via the advanced API. |
| melonDS `GP3D` VertexRAM+PolygonRAM (the current frame's 3D scene, regenerated by the game every frame, CPU-unreadable) is 23–66% of NDS delta bytes. The GBA m4a `SoundInfo.pcmBuffer` (3,168 B mixed PCM, refilled every VBlank, DMA-only) is ~60% of Emerald delta bytes. | Phase 2 masks them in *delta* keyframes; restart keyframes stay exact. |

Projected whole-file sizes at unchanged keyframe density:

| | HeartGold 2.3 GiB | White 2 3.1 GiB | Emerald 115 MiB |
|---|---|---|---|
| Phase 1 (lossless), zstd 9 | 519 MiB (4.5×) | 880 MiB (3.6×) | 50 MiB (2.3×) |
| Phase 1 + Phase 2 masks, zstd 9 | 345 MiB (6.7×) | 506 MiB (6.3×) | 21 MiB (5.5×) |

Tried and rejected (measured worse or no better): XOR-with-previous + zstd, byte-shuffle transforms, `zstd --patch-from`, per-keyframe independent compression, 2/8/16/32-byte diff granularity, anchoring restarts against frame 0 (unnecessary once chains are long).

## 3. How it works today (the parts this spec touches)

File paths are stable; line numbers are omitted. `resume-from-replay-spec.md` §2 documents the rest.

- **`util.rs` — `fast_diff` / `apply_diff`.** Word diff → `Vec<u64>`; bails out (`None`) if more than 1/8 of words differ or the lengths differ. `apply_diff` pads to a multiple of 4, applies, truncates.
- **`packet.rs` / `packet/io.rs`.** `Packet::DeltaKeyframe { metadata, diff: Vec<UnsignedInteger> }`, discriminator `0xF5`. `Packet::read_all(from, version)` already threads the header version through.
- **`replay_file/record.rs` — `ReplayFileRecorder::insert_keyframe`.** Diffs against `last_state_to_diff`; splits the blob (`next_blob`) when `current_blob_size_undiffed >= settings.minimum_uncompressed_bytes_per_blob`, where each delta keyframe adds `state.len()` to the estimate. `next_blob` compresses `current_blob` with `crate::compress_data` (one-shot `ZSTD_compress`), writes the `CompressedBlob` to the final sink, truncates the temp sink back and re-appends it.
- **`replay_file/playback.rs`.** `ReplayFilePlayer::new` eagerly converts top-level `DeltaKeyframe`s into `Keyframe`s. `decompress_compressed_blob` does the same for every blob. `next_packet()` hands out `&Packet` (via `launder_reference`) from the top-level list or the current blob's decompressed list; `go_to_keyframe` finds the blob by scanning `CompressedBlob.keyframes` metadata, decompresses it, then scans for the `Keyframe` packet.
- **`replay_file/header.rs`.** `REPLAY_VERSION = 3`, `REPLAY_VERSION_MINIMUM_SUPPORTED = 2`. Readers reject versions outside that range.
- **`supershuckie-core/src/lib.rs`.** `push_keyframe_if_needed` → `recorder.insert_keyframe(state, ms)`. `go_to_replay_frame(frame)` seeks the keyframe ≤ `frame-1`, loads it, then runs unlocked until `total_frames > frame-1` — i.e. **at least one** emulated frame after every keyframe load. `handle_replay` loads `Packet::Keyframe.state` when `auto_resync_keyframes_in_replays` is on.
- **`supershuckie-frontend/src/settings.rs` — `ReplaySettings`.** `max_recording_blob_size_mb` (1024) → `minimum_uncompressed_bytes_per_blob`; `zstd_compression_level` (3); `frames_per_keyframe` (120). These are JSON-only; the Qt UI does not expose them.
- **`record/resume.rs` — `build_resumed_recorder`.** Copies completed blobs verbatim, then re-feeds the straddling blob's packets into a fresh recorder through the public API (`next_frame`, `set_input`, `insert_keyframe`, …). It only ever sees full `Keyframe`s from the player.

## 4. Design overview

Format **v4**. Five independent pieces, each shippable on its own; §11 gives the commit order.

1. **`RegionDeltaKeyframe` packet** (new discriminator `0xF7`): run-length region diff against the previous keyframe. Replaces `DeltaKeyframe` for writing; `DeltaKeyframe` (`0xF5`) remains readable forever.
2. **Recorder:** no bail-out; chains bounded by *frames* (default 54,000 ≈ 15 min) and by *actual* buffered bytes; zstd through the advanced API at level 9.
3. **Player:** lazy materialisation — deltas stay compact after decompression and are applied on demand by a `ChainState` cursor. This is what makes long chains affordable and seeks cheaper.
4. **Transient-buffer masks** (Phase 2): `keyframe_masks::transient_ranges(console, state)` returns byte ranges the recorder copies from the previous keyframe before diffing. Pure function of the state bytes; used identically by live recording and the converter.
5. **`supershuckie-replay-convert`** CLI: v2/v3/v4 → v4, reusing the resume re-feed machinery, with a `--verify` mode.

Header version bumps to 4. New builds read 2..=4; old builds refuse v4 with the existing "unrecognized replay format version" error, which is the intended behaviour.

## 5. Phase 0 — settings only (do this today, no code)

In `settings.json` set `"replay": { "zstd_compression_level": 9 }`. Measured on the current format: −8% (NDS) / −18% (GBA) at 132–177 MiB/s. Level 19 gives −27% / −34% but costs 4–11 s of recorder-thread CPU per blob (the unbounded `mpsc` channel in `NonBlockingReplayFileRecorder` absorbs the stall; queued keyframe states are ~19 MiB each, so a few seconds is fine). **Do not raise `max_recording_blob_size_mb`** on the current format — it scales the player's per-blob expansion.

## 6. Phase 1 — format v4 (lossless)

### 6.1 Region diff — `supershuckie-replay-recorder/src/util.rs`

```rust
/// Run-length region diff at 4-byte granularity.
///
/// Both buffers are viewed as `ceil(len / 4)` little-endian words; a trailing partial word is
/// zero-padded for comparison and encoding (same convention as `apply_diff`).
///
/// `control` is a sequence of unsigned-LEB128 pairs `(gap, len)`: `gap` = unchanged words since
/// the end of the previous run (from word 0 for the first run), `len` = changed words (>= 1).
/// `data` is the concatenation of each run's `len * 4` replacement bytes, in order.
#[derive(Clone, PartialEq, Debug, Default)]
pub struct RegionDiff {
    pub control: Vec<u8>,
    pub data: Vec<u8>,
    pub runs: usize,
}

/// Returns `None` only when the lengths differ.
#[must_use]
pub fn region_diff(prev: &[u8], cur: &[u8]) -> Option<RegionDiff>;

/// Returns `None` if the diff is malformed (run past the end, leftover `data`, bad LEB128).
#[must_use]
pub fn apply_region_diff(prev: &[u8], control: &[u8], data: &[u8]) -> Option<Vec<u8>>;

/// Total encoded size; the recorder writes a full keyframe instead when this is not smaller
/// than `state.len()`.
impl RegionDiff { pub fn encoded_len(&self) -> usize { self.control.len() + self.data.len() } }
```

Implementation notes:
- Walk both inputs with `as_chunks::<4>()` comparing `u32`s (as `fast_diff` does); a scalar loop is fine — an 18.8 MiB state compares in a few ms.
- Keep `fast_diff` / `apply_diff`: `apply_diff` is still needed to read v2/v3 `DeltaKeyframe`s. `fast_diff` becomes test-only (`#[cfg(test)]`) or is deleted along with the write path; either is fine.
- LEB128 helpers are ~15 lines; put them next to the diff. Do **not** reuse the packet varint (`UnsignedInteger::write_packet_instructions`) inside the control stream — it costs 2 bytes for every value < 256.

### 6.2 Packet — `packet.rs`, `packet/io.rs`

```rust
/// A keyframe stored as a region diff against the previous keyframe in the same chain
/// (top-level stream or blob). The player materialises it on demand; see `playback::ChainState`.
RegionDeltaKeyframe {
    metadata: KeyframeMetadata,
    state_len: UnsignedInteger,
    control: ByteVec,
    data: ByteVec,
},
```

- `PacketDiscriminator::RegionDeltaKeyframe = 0xF7`.
- Serialise as `metadata`, `state_len`, `control` (ByteVec), `data` (ByteVec) — exactly like the neighbours in `write_packet_instructions` / `read_all`. `state_len` lets the reader validate before applying.
- `get_discriminator_byte` and both `match`es gain an arm. `Packet` is public: `supershuckie-core/src/lib.rs::handle_replay` and `record/resume.rs::prime_and_refeed` have exhaustive matches — add the arm next to `DeltaKeyframe` in each (both treat it as "the player should have materialised this"; resume returns `BadSource`, the core ignores it).

### 6.3 Recorder — `replay_file/record.rs`, `record/thread.rs`

**Settings.**

```rust
pub struct ReplayFileRecorderSettings {
    /// Hard cap on *actual* buffered uncompressed packet bytes before a blob is closed.
    /// (v3 counted every delta keyframe as a full state; that estimator is gone.)
    pub minimum_uncompressed_bytes_per_blob: usize,      // default unchanged: 1 GiB
    /// Close the blob at the first keyframe at or after this many frames since the blob's first
    /// keyframe. 0 = unlimited. Default 54_000 (15 min at 60 fps).
    pub max_frames_per_blob: u64,
    /// zstd level. Default 9 (was 3).
    pub compression_level: i32,
    /// Phase 2: copy transient output buffers from the previous keyframe before diffing.
    pub mask_transient_buffers: bool,                     // default true once Phase 2 lands
}
pub const DEFAULT_MAX_FRAMES_PER_BLOB: u64 = 54_000;
pub const DEFAULT_ZSTD_COMPRESSION_LEVEL_V4: i32 = 9;
```

**`insert_keyframe(state, elapsed_millis)`** becomes:

```text
if blob has keyframes
   && ((max_frames_per_blob > 0 && elapsed_frames - blob_first_frame >= max_frames_per_blob)
       || current_blob.len() >= minimum_uncompressed_bytes_per_blob)
{ next_blob(); last_state_to_diff = None; }

metadata = …(as today)…
let mut state = state;                              // ByteVec → make mutable
match last_state_to_diff {
    Some(prev) if prev.len() == state.len() => {
        if settings.mask_transient_buffers { apply_masks(console_type, &prev, &mut state); }   // Phase 2
        let d = region_diff(&prev, &state).unwrap();
        if d.encoded_len() < state.len() {
            write RegionDeltaKeyframe { metadata, state_len, control: d.control, data: d.data }
        } else {
            write Keyframe { metadata, state }
        }
    }
    _ => write Keyframe { metadata, state }
}
last_state_to_diff = Some(state);                   // the state AS WRITTEN (masked if masked)
```

- Record `blob_first_frame` when the first keyframe of a blob is written (it is `current_blob_keyframes[0].elapsed_frames`; no new field strictly needed).
- Delete `current_blob_size_undiffed`; `write_packet_unchecked` already tracks real bytes via `current_blob.len()`.
- `last_state_to_diff` must hold the masked state so the chain diffs against what the player will reconstruct (§7.3).
- `prime_for_resume` keeps clearing `last_state_to_diff` (a resumed blob starts with a full keyframe, as today).
- `thread.rs`: no signature changes are required for Phase 1; masks are a recorder setting, not a per-call argument.

**Compression — `util.rs::compress_data`.** Switch to the advanced API so parameters can be set:

```text
cctx = ZSTD_createCCtx()
ZSTD_CCtx_setParameter(cctx, ZSTD_c_compressionLevel, level.clamp(min, max))
if data.len() > 8 MiB:
    ZSTD_CCtx_setParameter(cctx, ZSTD_c_windowLog, min(27, ceil_log2(data.len())))
    ZSTD_CCtx_setParameter(cctx, ZSTD_c_enableLongDistanceMatching, 1)
n = ZSTD_compress2(cctx, dst, dst_cap, src, src_len)
ZSTD_freeCCtx(cctx)
```

`decompress_data` (one-shot `ZSTD_decompress` into a buffer of the exact `uncompressed_size`) needs no window buffer and already handles any `windowLog ≤ 27`. zstd-sys 2.0.16 exposes `ZSTD_createCCtx`, `ZSTD_CCtx_setParameter`, `ZSTD_compress2`, `ZSTD_freeCCtx` and the `ZSTD_cParameter` constants; check whether the binding renders the enum as a Rust `enum` or as `ZSTD_cParameter_ZSTD_c_…` constants and use whichever it is.

*Optional (1c): incremental compression.* Hold a `ZSTD_CStream` per in-progress blob, feed each packet as it is written and call `ZSTD_compressStream2(…, ZSTD_e_flush)` after every keyframe; `ZSTD_e_end` in `next_blob`. Output is still one frame that `ZSTD_decompress` reads, the temp sink still gets raw packets, and level 19 becomes ~30 ms per keyframe instead of seconds per blob (−25% vs level 3 on region-diff data, −10% vs level 9). Do this only after 1a/1b are in and measured.

### 6.4 Player — `replay_file/playback.rs` (lazy materialisation)

Remove both eager expansions (the loop in `ReplayFilePlayer::new` and the tail of `decompress_compressed_blob`). Keep the check that a blob's first packet is a full `Keyframe`, and add the equivalent for the top-level list: a `DeltaKeyframe`/`RegionDeltaKeyframe` must be preceded (in the same list) by a `Keyframe` — enforce during the indexing pass, honouring `allow_some_corruption`.

Add:

```rust
/// The state of the keyframe most recently passed by the cursor, and where it came from.
struct ChainState {
    /// `None` = top-level packet list; `Some(i)` = decompressed list of blob at top-level index i.
    list: Option<usize>,
    /// Index within that list of the last Keyframe/delta folded into `state`.
    last_applied: Option<usize>,
    state: Vec<u8>,
}
struct ReplayFilePlayer { …, chain: ChainState, materialized: Option<Packet> }
```

Invariant: whenever the cursor sits just after a keyframe-class packet, `chain.state` equals that keyframe's full state. Both `next_packet` and `go_to_keyframe` maintain it.

**`next_packet()`** — when the packet about to be returned is:
- `Keyframe { state, .. }`: `chain = { list, index, state.clone() }`; return the packet reference as today.
- `DeltaKeyframe { diff, .. }` (v3) or `RegionDeltaKeyframe { .. }`: require `chain.list == this list && chain.last_applied == Some(previous keyframe index)` (debug-assert; on violation return `BrokenPacket`). Apply (`apply_diff` / `apply_region_diff`) into `chain.state`, set `chain.last_applied`, then
  `self.materialized = Some(Packet::Keyframe { metadata: metadata.clone(), state: ByteVec::Heap(chain.state.clone()) })` and return `self.materialized.as_ref()` through the same `launder_reference` trick used today. The slot is overwritten by the next keyframe-class packet; every caller (`handle_replay`, `go_to_replay_frame_inner`, `prime_and_refeed`, `export.rs`) consumes the reference before calling `next_packet` again, which is the existing contract.
- Anything else: unchanged.

One 18.8 MiB clone per keyframe passed (every 2 s of playback) is ~5 ms; acceptable. Do not try to hand out `&chain.state` directly — the borrow gymnastics are not worth it.

**`go_to_keyframe(k)`** — after locating the list and packet index `target` (existing search, extended to match the two delta variants at top level and inside blobs), fast-forward the chain:

```text
start = if chain.list == list && chain.last_applied.map_or(false, |i| i < target)
        { chain.last_applied + 1 } else { 0 }        // list[0] is always a full Keyframe
for i in start..target:
    match list[i] { Keyframe → chain.state = state.clone(); Delta → apply into chain.state; _ → () }
    update chain.{list, last_applied}
set cursor to `target` (next_packet() then materialises k itself)
```

A cold seek into a 15-minute NDS chain = decompress ~50 MiB (30–60 ms measured for 30 MiB) + apply ≤ 450 region diffs (~100–200 KiB of copies each, ~20–50 ms). Forward seeks inside the current chain are incremental. The `all_keyframes()` / `all_bookmarks()` indexes are unchanged (they are built from metadata, which both delta variants carry — extend `add_keyframe!` to the new variants at top level).

**Other player changes.**
- `decompress_all_blobs` now holds compact packet lists (~100 MiB per 15-minute NDS chain), so `auto_decompress_replays_upfront` becomes usable for NDS. Document that in the setting's doc comment.
- `hint_decompress_next_blob_and_cleanup` and the threaded prefetch are untouched; `chain.state` is owned, so dropping old lists is safe.
- `ReplaySeekError` / `ReplayFileReadError`: add a `BrokenPacket`-style error for a delta that fails to apply on seek instead of `unreachable!`.

`REPLAY_VERSION = 4`; `REPLAY_VERSION_MINIMUM_SUPPORTED` stays 2. `KeyframeMetadata::read_all` keeps its `version >= 3` branch. No new header fields are needed: masking is not a per-file property (§7.3), and the packet discriminators self-describe. Update the "Resume support" comment block to mention v4.

### 6.8 Converter — `supershuckie-replay-recorder/src/bin/supershuckie-replay-convert.rs` (feature `std`)

```text
supershuckie-replay-convert <in.replay> <out.replay>
    [--level 9] [--chain-frames 54000] [--no-masks] [--verify] [--allow-corruption]
```

Implementation reuses the resume path, which already re-feeds a whole file through the recorder API:

1. `bytes = memmap2::Mmap` (add `memmap2` to the bin's deps; `std::fs::read` also works but doubles RAM for 5 GiB inputs) → `ReplayFilePlayer::new(&bytes, allow_corruption)`.
2. `build_resumed_recorder(&mut player, None, settings, ResumeCropPolicy::PreserveAll, BufWriter(out), NullReplayFileSink)` with a new option that **skips `copy_completed_blobs_before_boundary`** — add `pub fn build_reencoded_recorder(...)` (or a `force_refeed: bool` on an options struct) so every blob is decompressed and re-fed rather than copied verbatim. `prime_and_refeed` with `target == total` is already the "graceful end" mode.
3. `recorder.close()`.
4. `--verify`: reopen both files; assert equal `get_total_frames()`, `get_total_milliseconds()`, header crop markers and patch; walk both packet streams in lockstep asserting identical non-keyframe packets and, for every keyframe, identical materialised states (bytes outside masked ranges when `--no-masks` was not given; all bytes otherwise).

Header metadata, patch data and crop/timer markers ride through `ReplayFileMetadata` unchanged. Expect ~2–5 min per 9-hour NDS file (dominated by region-diffing 16K states and zstd 9); a batch script over the archive should keep originals until `--verify` passes.

## 7. Phase 2 — transient-buffer masks

### 7.1 What is masked and why it is safe

| Console | Buffer | Why it is output-only |
|---|---|---|
| NDS (melonDS) | `GP3D` section: `VertexRAM[2][6144]` (12,288 × 64 B) and `PolygonRAM[2][2048]` (4,096 × 188 B) | The geometry engine's polygon/vertex banks. Written by the GX FIFO, read only by the rasteriser; the CPU cannot read them. The game re-submits the whole scene every frame it renders 3D. |
| GBA (mGBA) | m4a `SoundInfo.pcmBuffer`, 1,584 × 2 bytes | The sound driver's mixed-PCM ring buffer, fully refilled every VBlank by the mixer and read only by the sound DMA. |

Masking a range means: **in delta keyframes, the range keeps whatever the chain's restart keyframe had.** Restart keyframes (first in each blob, and frame 0) are always exact. After loading a delta keyframe the emulator therefore has *stale but internally consistent* geometry/audio for at most one frame: melonDS rebuilds its `Polygon.Vertices` pointers from the stored indices on load and every stored index stays valid (verified: all 4,096 polygons and the render list parse cleanly), and the game overwrites the buffers on its next frame. Nothing the CPU computes depends on either buffer, so determinism — and therefore playback and resume — is unaffected.

### 7.2 `supershuckie-replay-recorder/src/keyframe_masks.rs`

```rust
/// Byte ranges of `state` that hold regenerated output buffers (see spec §7.1).
/// Returns nothing unless every layout check passes, so an unexpected core version silently
/// falls back to lossless behaviour.
pub fn transient_ranges(console: ReplayConsoleType, state: &[u8]) -> Vec<core::ops::Range<usize>>;

pub(crate) fn apply_masks(console: ReplayConsoleType, prev: &[u8], cur: &mut [u8]) {
    for r in transient_ranges(console, cur) { cur[r.clone()].copy_from_slice(&prev[r]); }
}
```

**NDS.** melonDS `Savestate` layout (`Savestate.cpp`, `GPU3D.cpp`, savestate version 13.0):
- File header 16 B: `"MELN"`, `u16 major`, `u16 minor`, `u32 length`, `u32 0`. Sections follow at offset 16: `[u8;4] magic`, `u32 section_len` (includes the 16-byte section header), 8 zero bytes, payload.
- Walk sections to `"GP3D"`. Require `major == 13` and `section_len == 1_572_864`.
- Constants, derived from `GPU3D::DoSavestate` field order and validated against real states: `VertexRAM` starts at `section_off + 7_409` (`0x1CF1`) and is `786_432` bytes; `PolygonRAM` follows immediately and is `770_048` bytes. Mask exactly `section_off + 7_409 .. section_off + 1_563_889`. `CmdStallQueue`, `RenderNumPolygons` and `RenderPolygonRAM` (the 8 KiB render list) come after and stay live.
- Gate additionally on `emulator_core_name == "melonDS 1.1 [SUPERSHUCKIE-EXPERIMENTAL-0]"` from the header if you want belt and braces; the `major`/`section_len` checks are the ones that matter. Add a unit test that builds a synthetic MELN buffer with a 1,572,864-byte GP3D section and asserts the returned range; add a second test with a wrong section length asserting an empty result.

**GBA.** mGBA `GBASerializedState` is `0x61000` bytes with `iwram` at `0x19000` (`gba/serialize.h`); `versionMagic` (first `u32`) is `0x01000000 + version` (currently `0x0100000A`). Every m4a/MP2K game keeps a pointer to its `SoundInfo` at `0x03007FF0`:
- Require `state.len() >= 0x61000` and `state[0..4] & 0xFFFF0000 == 0x01000000`.
- `ptr = u32_le(state[0x19000 + 0x7FF0..])`; require `0x03000000 <= ptr` and `ptr + 0xFB0 <= 0x03008000`.
- `si = 0x19000 + (ptr - 0x03000000)`; require `u32_le(state[si..]) == 0x68736D53` (`"Smsh"`, the driver's ident).
- Mask `si + 0x350 .. si + 0x350 + 0xC60` (`pcmBuffer` follows the 0x50-byte header and 12 × 0x40-byte `SoundChannel`s; `PCM_DMA_BUF_SIZE = 1584`, double-buffered). Verified on Emerald (`SoundInfo` at `0x03006380`) and FireRed (`0x03005F50`) states; the observed 100%-rewritten span matches to the byte.
- Games without the driver (ident mismatch) get no mask. Re-evaluate per keyframe — it is a few reads.

**GB / GBC / SGB:** no masks.

### 7.3 Recorder integration

Already sketched in §6.3: `apply_masks(header.console_type, &prev, &mut state)` before `region_diff`, and `last_state_to_diff = state (masked)`. Because the mask copies the *reconstructed previous* bytes forward, the masked range contributes zero runs to every delta in the chain, and the chain stays self-consistent without any reader-side knowledge — a v4 reader does not need to know whether a file was masked. `ReplayFileRecorderSettings::mask_transient_buffers` gates it; the converter's `--no-masks` clears it.

### 7.4 Core changes — `supershuckie-core/src/lib.rs`

- **Seek lands ≥ 3 emulated frames after the keyframe load.** Today `go_to_replay_frame(frame)` calls `go_to_replay_frame_inner(frame-1, frame-1)`, which can emulate exactly one frame after loading; that one frame would render the stale 3D bank. Change to:

  ```rust
  const POST_LOAD_FRAMES: u64 = 3;
  pub fn go_to_replay_frame(&mut self, frame: UnsignedInteger) {
      let hint = frame.saturating_sub(POST_LOAD_FRAMES);   // keyframe <= frame - 3
      let desired = frame.saturating_sub(1);               // run until total_frames == frame
      self.go_to_replay_frame_inner(hint, desired);
  }
  ```

  `go_to_replay_frame_inner` is unchanged (it still resolves `NoSuchKeyframe { best }` by recursing). Three frames covers games that only resubmit geometry every other frame; the cost is <10 ms. `attach_replay_player`'s `go_to_replay_frame_inner(0, 0)` is fine — frame 0 is an exact restart keyframe. `export.rs` seeks through the same function.

- **Resync splice.** In `handle_replay`'s `Packet::Keyframe` arm, when `auto_resync_keyframes_in_replays` is on: copy the keyframe state, take `self.core.create_save_state()` (the live emulator is at the same frame), overwrite `transient_ranges(console, &state)` from the live state, then load. Resync then never flashes a stale frame in the normal (in-sync) case. Skip the splice if lengths differ.

### 7.5 Interaction with resume

`prime_and_refeed` re-inserts materialised (masked) states through `insert_keyframe`, which re-masks them against the same bytes — a no-op — so resumed files stay consistent. Note the one wrinkle: the boundary keyframe of a resumed/converted file is written as a *restart* from a reconstructed state, so its masked region is stale rather than exact. That is invisible (a restart is loaded the same way as any keyframe) but worth a comment in `prime_and_refeed`. Frame 0 is always exact. Blobs copied verbatim by resume keep their source encoding; run the converter to shrink a file resumed from a v3 source.

## 8. Edge cases & failure handling

- **State length changes between keyframes** (possible after `LoadSaveState` of a differently-sized state, or a core that varies state size): `region_diff` returns `None` → write a full `Keyframe`, exactly as v3 does today.
- **A delta that is not smaller than the state** (whole-RAM rewrite): full `Keyframe`. Never observed, but keep the check — it keeps the size bound trivially true.
- **Malformed delta on read:** `apply_region_diff` → `None` → `ReplayFileReadError::BrokenPacket` (`ReplaySeekError::ReadError` from `go_to_keyframe`). In `allow_some_corruption` mode the player stops at that packet, as it does for other parse failures.
- **Crash-safe temp files:** the top-level tail now contains compact `RegionDeltaKeyframe`s (up to 15 minutes of them); the lazy top-level chain handles it. Confirm `continue_last_replay` / temp-file recovery still opens and seeks such a file.
- **v3 files:** fully readable; `DeltaKeyframe` (`0xF5`) is materialised by the same `ChainState`. A v4 file produced by *resume* from a v3 source legitimately contains v3-encoded blobs; readers must accept both discriminators regardless of header version.
- **Old builds vs v4 files:** refused with the existing version-range error. Acceptable and intended.
- **Memory bounds:** recorder holds ~19 MiB `last_state_to_diff` + the raw in-progress blob (~70–110 MiB for a 15-minute NDS chain); player holds `chain.state` + `materialized` (~38 MiB) + ~100 MiB per decompressed chain (×2 with prefetch). Whole-file `fs::read` + the `ByteVec` copy of each blob (2× file size) is unchanged in this spec; with 4–6× smaller files it stops mattering, and mmap-backed blob slices can be a follow-up.
- **Chain length vs seek latency:** `max_recording_blob_minutes` is the knob. 15 minutes ≈ 50–100 ms cold seek on NDS; 60 minutes would be ~4× that and save only a few more MiB per hour.

## 9. Testing plan

Unit tests live next to the code (the crate has `// TODO: WRITE UNIT TESTS` markers; `record/resume.rs` shows the harness style — synthetic states, `Vec<u8>` sinks, small blob limits).

1. **`region_diff` / `apply_region_diff`:** identity (0 runs, empty `data`); single changed word at start / middle / end; adjacent runs merge; trailing partial word (lengths 1, 2, 3 mod 4); length mismatch → `None`; malformed control (run past end, leftover data) → `None`; property test with random states and random sparse edits: `apply(prev, diff(prev, cur)) == cur`.
2. **Packet round trip:** `RegionDeltaKeyframe` through `write_packet_instructions` → `read_all` at version 4.
3. **Recorder → player equivalence:** record N synthetic keyframes with `max_frames_per_blob` small enough to produce several blobs and a top-level tail (do not close the recorder for the tail case; read the temp sink). For every keyframe `k`, `go_to_keyframe(k)` + `next_packet()` must yield the exact recorded state; exercise forward, backward and cross-blob seek orders, and sequential playback from 0 to the end checking each materialised keyframe.
4. **Fallbacks:** a keyframe whose length changed and one that is rewritten entirely produce full `Keyframe`s and the chain continues correctly afterwards.
5. **v3 compatibility fixture:** before changing the writer, generate a small v3 file (`tests/fixtures/v3-small.replay`, ~100 KiB, with both top-level and in-blob `DeltaKeyframe`s) and assert the new player materialises identical states and the same frame/millis totals. Keep the fixture in the repo.
6. **Masks:** synthetic MELN buffer → exact expected range; wrong section length / wrong major → empty. Synthetic mGBA buffer with a valid `Smsh` block → expected range; bad pointer / bad ident → empty. Recorder test with masks on: reconstructed states equal the recorded ones outside the range and equal the restart's bytes inside it.
7. **Resume tests** in `record/resume.rs` must keep passing unchanged (they go through the same public API).
8. **Converter:** v3 fixture → v4 → `--verify` passes with and without masks; output is smaller.
9. **Real files (manual, before flipping defaults):** convert `h-ampharos-line-1-21318.replay` and `e-geodude-1-20359.replay`; sizes should land within ±15% of §2's projections; open each in the app: scrub across blob boundaries, play through a keyframe with resync on, resume from the middle, export a short video. On the NDS file with masks, step frame-by-frame after a seek and confirm no 3D artefact is visible in the presented frame.

Everything in §5-§7 landed (commits `38a3f86..3aa955a`); the optional items of §11 step 8
(incremental zstd, mmap-backed blob slices) were not done. Measured with `supershuckie-replay-convert`
on the §2 sample files, every run passing `--verify`:

|---|---|---|---|---|
| Emerald `e-geodude-1-20359` | 115.2 MiB | 52.4 MiB (2.20x) | 23.6 MiB (4.88x) | <= 62 / <= 28 MiB |
| HeartGold `h-ampharos-line-1-21318` | 2.3 GiB | 353.7 MiB (6.57x) | 191.6 MiB (12.1x) | <= 620 / <= 420 MiB |
| White 2 `w-butterfree-line-1-22109` | 3.1 GiB | (not run) | 278.2 MiB (11.4x) | <= 1.05 GiB / <= 620 MiB |

NDS lands well below the §2 projections because `compress_data` now gives blobs above 8 MiB a
128 MiB window plus long-distance matching, so the near-identical replacement bytes of consecutive
keyframe deltas (the 3D banks especially) match across the whole chain.

Conversion cost: ~20 ms per NDS keyframe, i.e. ~5 min + ~5.5 min verify for a 2h15 NDS replay
(Emerald: 9 s + 9 s). Files convert independently, so batch the archive several processes at a time
(each needs RAM ~= its input size).

Seek latency (`examples/seek_bench.rs`, converted HeartGold): cold seek into another 15-minute
chain 110-175 ms, forward hop within the chain 8-10 ms; masked file 54 ms average over mixed seeks.

Not verified in the app (the production instance was running and owns the REST port, so no second
instance was driven): §9.9's manual checks — scrub across blob boundaries, play through a keyframe
with resync on, resume from the middle, export a short video, and step frame-by-frame after a seek
on a masked NDS file looking for 3D artefacts.
